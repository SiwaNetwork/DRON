# 1 Общие сведения

1.1 Наименование программы — встроенное программное обеспечение микроконтроллера модуля
приёмника ГНСС МГП-8 (далее — ПО МК). Обозначение — ШИВА.00001-01.

1.2 ПО МК выполняется на микроконтроллере STM32H743 (Cortex-M7, 480 МГц) в составе
модуля МГП-8 (ШИВА.468157.001). Для проверок ПО МК без изменений исходных текстов
собирается на ПК: вместо шины FMC используется битово-точная модель ПЛИС.

1.3 Язык программирования — C (стандарт C99). Математическая библиотека — стандартная
(libm). На МК БПФ выполняется функциями CMSIS-DSP, на ПК — собственной реализацией
(`src/fft.c`).

1.4 Исходные тексты — каталог `sw/fw`:

- `inc/` — заголовки;
- `src/` — модули;
- `tests/` — тесты;
- `tools/` — генераторы таблиц кодов и эталонных векторов.

Сборка и проверка на ПК — `make test` и `make test-long`.

# 2 Функциональное назначение

2.1 ПО МК управляет ПЛИС и ВЧ-трактами модуля и решает навигационные задачи:

- захват сигналов по снимкам отсчётов: обычный режим и режим длительного накопления;
- слежение по результатам аппаратного коррелятора (80 каналов);
- декодирование навигационного сообщения GPS LNAV, хранение эфемерид;
- измерение псевдодальностей и доплеровских сдвигов;
- двухчастотные измерения GPS L1 C/A + L2C: пуск канала L2CM по каналу L1 того же КА
  (без поиска), ионосферно-свободная комбинация псевдодальностей;
- навигационное решение (координаты, скорость, смещение и дрейф часов, DOP);
- формирование метки времени 1PPS с поправкой дискретности qErr;
- выдача протоколов NMEA-0183 и RTCM 3.3;
- спектральный контроль ВЧ-каналов, обнаружение узкополосных помех, настройка
  режекторного фильтра ПЛИС.

2.2 Ограничения текущей версии:

- разработано и проверено на ПК вычислительное ядро ПО МК. Платформенная часть
  разрабатывается при изготовлении опытного образца: начальный запуск, драйверы UART,
  USB, CAN, SDMMC, загрузчик, планировщик задач;
- навигационные сообщения Galileo и BeiDou не декодируются: коды сигналов и расчёт
  координат КА этих систем реализованы, но декодеров сообщений нет. ГЛОНАСС L1OF
  поддерживается полностью, в том числе без GPS (дата — по строке 5);
- двухчастотный режим реализован для пары GPS L1 C/A + L2CM по псевдодальностям;
  сглаживание по фазе и другие пары частот (L5, E5a, B2a, ГЛОНАСС L2) не реализованы;
- захват по снимкам выполняется для сигналов с размером БПФ до 16 384 точек:
  L1 C/A, B1I, ГЛОНАСС L1/L2. Остальные сигналы захватываются с поддержкой
  от сигналов L1 того же КА (известны время и доплер).

## 3.2 Обмен с ПЛИС

3.2.1 Регистры ПЛИС отображены в адресное пространство МК через FMC (банк 1). Карта
регистров — `inc/fpga.h`, которая совпадает с описанием в `fpga/rtl/mgp8_core.v`.
Доступ — функции `fpga_rd` и `fpga_wr`. На ПК они перенаправляются в модель
`corr_sim.c`.

3.2.2 Время в ПО МК задаётся номером отсчёта (24 МГц, 64 бит) и счётчиком тактов
T96 ПЛИС. Время излучения сигнала КА определяется по формуле

t_tx(n) = ref_tow + (code_tot(n) − ref_code) / 2^32 / R_code.

Обозначения:

- ref_tow — TOW конца подкадра;
- ref_code — полная фаза кода на эпохе конца подкадра;
- code_tot(n) — полная (без свёртки) фаза кода на отсчёте n из «зеркала» NCO.

«Зеркало» NCO повторяет состояние аппаратного NCO по записанным шагам. Смена шагов
вступает в силу в конце группы из четырёх отсчётов, содержащей сброс, как и в ПЛИС.

## 3.3 Порядок работы

3.3.1 После включения ПО МК выполняет инициализацию:

1) ожидание загрузки конфигурации ПЛИС (из флеш-памяти W25Q128), проверка регистра ID;
2) настройка MAX2771 по SPI через ПЛИС;
3) выбор фазы приёма отсчётов.

3.3.2 Захват и пуск каналов:

1) снимки по каждому ВЧ-каналу, поиск всех PRN сигналов канала;
2) загрузка кода, настройка NCO и синхронный пуск каналов с заданного отсчёта
   (START_T/START_MASK);
3) при отсутствии сигналов на уровне обычного режима — режим длительного накопления.

3.3.3 Прерывание ПЛИС по готовности сбросов (период — 1 мс или период кода) запускает:

- чтение результатов;
- шаг петель слежения;
- запись новых шагов NCO;
- выделение битов и передачу их декодеру сообщения.

3.3.4 Раз в период решения (1–20 Гц) по номеру отсчёта эпохи выполняются:

1) измерения;
2) навигационное решение;
3) расчёт момента следующего 1PPS — запись PPS_T в ПЛИС;
4) выдача протоколов.

3.3.5 Фоновые задачи: спектральный контроль каналов (снимок, спектр, обнаружение помех,
настройка фильтра), запись на карту microSD, обработка команд.

## 3.4 Алгоритмы

3.4.1 **Обычный захват.** Перенос на нулевую частоту по ячейкам доплера, усреднение периода
кода в 2^k ячеек (не менее 4 на чип), круговая корреляция с копией через БПФ,
некогерентное накопление по периодам и снимкам. Сдвиг пика из-за доплера кода
между снимками компенсируется. Решение принимается по отношению пика ко второму пику.
Затем доплер уточняется прямой корреляцией в найденной фазе кода.

3.4.2 **Захват слабых сигналов.** Потоковое накопление K периодов (до 256) по свежим
снимкам для группы PRN. Решение принимается по критерию постоянной вероятности
ложной тревоги: z = (пик / среднее − 1)·√K > 6,5. Буферы для группы из 8 PRN —
384 КБ.

3.4.3 **Слежение.** Используются:

- ФАП 2-го порядка (15 Гц) с поддержкой ЧАП (10 Гц) на этапе втягивания; в захвате —
  ФАП 3-го порядка (18 Гц), рассчитанная на динамику 4g с рывком 2g/с;
- ССЗ 1-го порядка (1 Гц) с поддержкой от несущей;
- нормированный дискриминатор «ранний минус поздний» по огибающей.

Индикатор захвата фазы и оценка C/N0 вычисляются по отношению мощностей.
При срыве более 1 с канал освобождается.

При C/N0 ниже 32 дБГц канал переходит к длительному накоплению:

- результаты периодов кода когерентно суммируются на 20 мс: по границам битов
  (L1 C/A) или со снятием вторичного кода (E1C — CS25, L5Q — NH20);
- петли обновляются раз в 20 мс (ФАП 5 Гц, ССЗ 0,2 Гц).

Синхронизация по вторичному коду выполняется сравнением знаков точного отвода со всеми
сдвигами кода. Она же снимает неоднозначность фазы, после чего ФАП пилота становится
четырёхквадрантной.

Повторный захват. При срыве в режиме накопления (индикатор ниже порога 200 мс подряд)
канал до 30 с ведёт NCO по прогнозу частоты. Появление сигнала обнаруживается по мощности
20-мс сумм (5 превышений из 8). Затем петли втягиваются заново; ложное обнаружение
отменяется через 1 с.

3.4.4 **Навигационное решение.** Взвешенный МНК с весами sin²(угол места). Неизвестные —
координаты и смещения шкал по системам. Учитываются:

- поправки часов КА (с релятивистской);
- вращение Земли за время распространения;
- тропосфера (Саастамойнен);
- ионосфера (Клобучар) — для одночастотных измерений;
- групповая задержка TGD КА GPS — для одночастотных измерений: часы КА в эфемеридах
  отнесены к ионосферно-свободной комбинации, на частоте f поправка −TGD·(f1/f)².

Скорость и дрейф часов определяются по доплеровским измерениям.

3.4.5 **Двухчастотный режим (GPS L1 C/A + L2C).** Канал L2CM пускается по каналу L1 C/A
того же КА после привязки времени излучения:

- фаза кода L2CM — по времени излучения L1: (t_tx mod 20 мс)·511,5 кГц;
- доплер — пересчётом доплера L1 по отношению несущих f2/f1.

Поиск не нужен: начальная ошибка по задержке определяется разностью ионосферных
задержек (единицы метров при длине чипа CM 586 м). Слежение ведётся по CM (период кода
и символа 20 мс); половины чипов CL в копии обнуляются (режим TDM коррелятора).

Псевдодальность L2 строится так. Время излучения внутри периода 20 мс берётся по фазе
кода L2CM, целое число периодов — по L1: разность времён излучения L2 и L1 приводится
к интервалу ±10 мс. Ионосферно-свободная комбинация:

P_IF = (γ·P1 − P2)/(γ − 1), γ = (f1/f2)² = (77/60)².

Для неё модель ионосферы и поправка TGD не применяются.

3.4.6 **1PPS.** Момент следующей секунды GPST вычисляется по последнему решению
с учётом дрейфа и пересчитывается в такт 96 МГц. Остаток квантования выдаётся как qErr.

3.4.7 **Помехи.** Используются спектр Уэлча (1024 точки, окно Ханна) и пики выше 6 дБ
над медианой. Частота уточняется максимумом ДПФ по снимку. Фильтр включается при
J/N ≥ −20 дБ, дизеринг — при J/N < −5 дБ.

# 4 Используемые технические средства

4.1 Микроконтроллер STM32H743 (1 МБ ОЗУ, 2 МБ флеш-памяти). ПЛИС модуля
с конфигурацией из `fpga/rtl` подключена к шине FMC (банк 1, 16 бит, мультиплексированный
режим, сигнал NWAIT).

4.2 Для проверок на ПК: Linux, gcc (C99), Python 3 с пакетами numpy, pynmeagps, pyrtcm.

4.3 Объём (вычислительное ядро, `make -C sw/fw mcu`, arm-none-eabi-gcc -O2, Cortex-M7):

- код и константы — 394 КБ, из них таблицы дальномерных кодов 357 КБ;
- статические данные — 452 КБ, из них буферы захвата 395 КБ;
- буферы режима длительного накопления — 384 КБ на группу из 8 PRN, выделяются
  в SRAM1–3 и DTCM.

Всего ОЗУ около 836 КБ из 1 МБ, флеш-памяти — менее 0,4 МБ из 2 МБ.

# 5 Вызов и загрузка

5.1 ПО МК загружается во флеш-память МК через SWD или через загрузчик по USB/UART.
Конфигурация ПЛИС хранится во флеш-памяти W25Q128 и загружается ПЛИС при включении.

5.2 На ПК: `make -C sw/fw test` — модульные и сквозные тесты; `make -C sw/fw test-long` —
сквозной тест «ПЧ → координаты, 1PPS».

# 6 Входные данные

6.1 Входные данные ПО МК:

- результаты корреляторов: I/Q трёх отводов, номер отсчёта сброса;
- снимки отсчётов каналов;
- метки времени событий ПЛИС (EXTINT, опора);
- состояние MAX2771 и питания антенны;
- команды по UART, USB и CAN.

6.2 Для проверок на ПК — отсчёты ПЧ от имитаторов в тестах и навигационные файлы
RINEX (IGS).

# 7 Выходные данные

7.1 Выходные данные ПО МК:

- сообщения NMEA-0183 4.11 (GGA, RMC, GSA, GSV, GST, ZDA);
- RTCM 3.3 (MSM7 для GPS, ГЛОНАСС, Galileo, BeiDou; 1005);
- собственный двоичный протокол: кадр 0x4D 0x38, класс, идентификатор, длина, данные,
  CRC-16/CCITT. Сообщения: решение (01/01), сырые измерения (02/01), эфемериды (02/02),
  состояние каналов (03/01), ИТМ (04/01);
- уставки 1PPS (регистр PPS_T) и поправка qErr;
- настройки режекторного фильтра ПЛИС.
