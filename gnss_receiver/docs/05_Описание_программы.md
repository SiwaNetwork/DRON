# 1 Общие сведения

1.1 Наименование программы — встроенное программное обеспечение микроконтроллера модуля
приёмника ГНСС МГП-8 (далее — ПО МК). Обозначение — ШИВА.00001-01.

1.2 ПО МК выполняется на микроконтроллере STM32H743 (Cortex-M7, 480 МГц) в составе
модуля МГП-8 (ШИВА.468157.001). Для проверок ПО МК без изменений исходных текстов
собирается на ПК: вместо шины FMC используется битово-точная модель ПЛИС.

1.3 Язык программирования — C (стандарт C99). Математическая библиотека — стандартная
(libm). На МК БПФ выполняется функциями CMSIS-DSP, на ПК — собственной реализацией
(`src/fft.c`).

1.4 Исходные тексты — каталог `sw/fw`:

- `inc/` — заголовки;
- `src/` — модули;
- `tests/` — тесты;
- `tools/` — генераторы таблиц кодов и эталонных векторов.

Сборка и проверка на ПК — `make test` и `make test-long`.

# 2 Функциональное назначение

2.1 ПО МК управляет ПЛИС и ВЧ-трактами модуля и решает навигационные задачи:

- захват сигналов по снимкам отсчётов: обычный режим и режим длительного накопления;
- слежение по результатам аппаратного коррелятора (80 каналов);
- декодирование навигационных сообщений GPS LNAV, ГЛОНАСС L1OF, Galileo I/NAV (E1-B)
  и BeiDou D1 (B1I), хранение эфемерид;
- измерение псевдодальностей и доплеровских сдвигов, сглаживание кода по фазе несущей;
- двухчастотные измерения по парам GPS L1 C/A + L2C или L5, ГЛОНАСС G1 + G2, Galileo
  E1-B + E5a, BeiDou B1I + B3I: пуск канала второй частоты по каналу первой того же КА
  (без поиска), ионосферно-свободная комбинация псевдодальностей с поправкой на групповую
  задержку комбинации;
- навигационное решение (координаты, скорость, смещение и дрейф часов, DOP) с весами
  по ожидаемому шуму измерений;
- формирование метки времени 1PPS с поправкой дискретности qErr;
- выдача протоколов NMEA-0183 и RTCM 3.3;
- спектральный контроль ВЧ-каналов, обнаружение узкополосных помех, настройка
  режекторного фильтра ПЛИС.

2.2 Ограничения текущей версии:

- разработано и проверено на ПК вычислительное ядро ПО МК. Платформенная часть
  разрабатывается при изготовлении опытного образца: начальный запуск, драйверы UART,
  USB, CAN, SDMMC, загрузчик, планировщик задач;
- навигационные сообщения декодируются для GPS LNAV, ГЛОНАСС L1OF (в том числе без GPS:
  дата — по строке 5), Galileo I/NAV и BeiDou D1. Не реализованы: BeiDou D2 (КА GEO,
  PRN 1–5, 59–63), Galileo F/NAV, сообщения ГЛОНАСС с кодовым разделением; ионосферная
  модель BeiDou в решение не передаётся (используются параметры GPS);
- двухчастотный режим реализован для пар L1 C/A + L2CM или L5Q, G1 + G2, E1-B + E5a-Q,
  B1I + B3I. Пара B1I + B2a не реализована: часы КА в сообщении D1 отнесены к B3I, а для
  B2a нужна групповая задержка TGD_B2ap из сообщения B-CNAV, которое не декодируется.
  Не реализована и помощь каналу второй частоты по несущей первой при высокой динамике;
- захват по снимкам выполняется для сигналов с размером БПФ до 16 384 точек:
  L1 C/A, B1I, ГЛОНАСС L1/L2 и E1-B (4 ячейки на чип; период 4 мс длиннее снимка —
  когерентно накапливается его часть). Остальные сигналы захватываются с поддержкой
  от сигналов L1 того же КА (известны время и доплер). Режим длительного накопления
  для E1 не реализован.

## 3.2 Обмен с ПЛИС

3.2.1 Регистры ПЛИС отображены в адресное пространство МК через FMC (банк 1). Карта
регистров — `inc/fpga.h`, которая совпадает с описанием в `fpga/rtl/mgp8_core.v`.
Доступ — функции `fpga_rd` и `fpga_wr`. На ПК они перенаправляются в модель
`corr_sim.c`.

3.2.2 Время в ПО МК задаётся номером отсчёта (24 МГц, 64 бит) и счётчиком тактов
T96 ПЛИС. Время излучения сигнала КА определяется по формуле

t_tx(n) = ref_tow + (code_tot(n) − ref_code) / 2^32 / R_code.

Обозначения:

- ref_tow — TOW конца подкадра (GPS, BeiDou), страницы I/NAV (Galileo) или метки
  времени строки (ГЛОНАСС), приведённый к GPST;
- ref_code — полная фаза кода на эпохе конца подкадра;
- code_tot(n) — полная (без свёртки) фаза кода на отсчёте n из «зеркала» NCO.

«Зеркало» NCO повторяет состояние аппаратного NCO по записанным шагам. Смена шагов
вступает в силу в конце группы из четырёх отсчётов, содержащей сброс, как и в ПЛИС.

3.2.3 У каждого движка коррелятора один регистр пуска (START_T/START_MASK). Пуск на другой
отсчёт до срабатывания ожидающего отменил бы ожидающий. Поэтому:

- пуски на один отсчёт объединяются в общую маску;
- пуск на другой отсчёт откладывается до срабатывания ожидающего (`corr_start_pending`).

## 3.3 Порядок работы

3.3.1 После включения ПО МК выполняет инициализацию:

1) ожидание загрузки конфигурации ПЛИС (из флеш-памяти W25Q128), проверка регистра ID;
2) настройка MAX2771 по SPI через ПЛИС;
3) выбор фазы приёма отсчётов.

3.3.2 Захват и пуск каналов:

1) снимки по каждому ВЧ-каналу, поиск всех PRN сигналов канала;
2) загрузка кода, настройка NCO и синхронный пуск каналов с заданного отсчёта
   (START_T/START_MASK);
3) при отсутствии сигналов на уровне обычного режима — режим длительного накопления.

3.3.3 Прерывание ПЛИС по готовности сбросов (период — 1 мс или период кода) запускает:

- чтение результатов;
- шаг петель слежения;
- запись новых шагов NCO;
- выделение битов и передачу их декодеру сообщения.

3.3.4 Раз в период решения (1–20 Гц) по номеру отсчёта эпохи выполняются:

1) измерения;
2) навигационное решение;
3) расчёт момента следующего 1PPS — запись PPS_T в ПЛИС;
4) выдача протоколов.

3.3.5 Фоновые задачи: спектральный контроль каналов (снимок, спектр, обнаружение помех,
настройка фильтра), запись на карту microSD, обработка команд.

## 3.4 Алгоритмы

3.4.1 **Обычный захват.** Перенос на нулевую частоту по ячейкам доплера, усреднение периода
кода в 2^k ячеек (не менее 4 на чип), круговая корреляция с копией через БПФ,
некогерентное накопление по периодам и снимкам. Сдвиг пика из-за доплера кода
между снимками компенсируется. Решение принимается по отношению пика ко второму пику.
Затем доплер уточняется прямой корреляцией в найденной фазе кода.

3.4.2 **Захват слабых сигналов.** Потоковое накопление K периодов (до 256) по свежим
снимкам для группы PRN. Решение принимается по критерию постоянной вероятности
ложной тревоги: z = (пик / среднее − 1)·√K > 6,5. Буферы для группы из 8 PRN —
384 КБ.

3.4.3 **Слежение.** Используются:

- ФАП 2-го порядка (15 Гц) с поддержкой ЧАП (10 Гц) на этапе втягивания; в захвате —
  ФАП 3-го порядка (18 Гц), рассчитанная на динамику 4g с рывком 2g/с;
- ССЗ 1-го порядка (1 Гц) с поддержкой от несущей;
- нормированный дискриминатор «ранний минус поздний» по огибающей.

Индикатор захвата фазы и оценка C/N0 вычисляются по отношению мощностей.
При срыве более 1 с канал освобождается.

Полосы петель ограничены условием Bn·T ≤ 0,1, где T — интервал обновления. Новые шаги
NCO действуют со следующего интервала, и при длинном периоде кода (L2CM — 20 мс) более
широкая петля теряет устойчивость. При периоде кода 10 мс и более (L2CM, L1C) ССЗ
работает в полосе 0,2 Гц с поддержкой от несущей.

Для сигналов с временным уплотнением (L2C) копия CM занимает первую половину чипа, и
главный пик корреляции вдвое уже: смещение E/L — ±0,25 чипа, коэффициент дискриминатора
рассчитан на полуширину пика 0,5 чипа.

При C/N0 ниже 32 дБГц канал переходит к длительному накоплению:

- результаты периодов кода когерентно суммируются на 20 мс: по границам битов
  (L1 C/A) или со снятием вторичного кода (E1C — CS25, L5Q — NH20);
- петли обновляются раз в 20 мс (ФАП 5 Гц, ССЗ 0,2 Гц).

Синхронизация по вторичному коду выполняется сравнением знаков точного отвода со всеми
сдвигами кода. Она же снимает неоднозначность фазы, после чего ФАП пилота становится
четырёхквадрантной.

Повторный захват. При срыве в режиме накопления (индикатор ниже порога 200 мс подряд)
канал до 30 с ведёт NCO по прогнозу частоты. Появление сигнала обнаруживается по мощности
20-мс сумм (5 превышений из 8). Затем петли втягиваются заново; ложное обнаружение
отменяется через 1 с.

3.4.4 **Навигационное решение.** Взвешенный МНК, вес измерения — sin²(угол места)/(σ² + σ²_ион).
Неизвестные — координаты и смещения шкал по системам.

σ² — ожидаемая дисперсия шума кода. Её рассчитывает модуль измерений по тепловому шуму ССЗ
с поддержкой от несущей (дискриминатор (E − L)/(E + L)):

σ² = h·s·Bn/(C/N0)·(1 + 1/(T·C/N0·(1 − s/h)))·λc²/m + σ0²,

где:

- h — полуширина пика корреляции: 1 чип, у L2C (TDM) — 0,5, у BOC(1,1) — 1/3;
- s — смещение отводов E/L;
- Bn — полоса ССЗ;
- T — время когерентного накопления;
- λc — длина чипа;
- m — эффективное число независимых измерений в сглаженной ПД (подраздел 3.4.6);
- σ0 = 0,3 м — остаточные ошибки, например многолучёвость.

Для ионосферно-свободной комбинации σ² = (γ²·σ1² + σ2²)/(γ − 1)².

σ²_ион — ошибка модели ионосферы для одночастотных измерений: (0,5·задержка по Клобучару)².

Веса нужны при смешивании сигналов с разной длиной чипа. В парах L1 + L5, E1 + E5a
и B1I + B3I шум комбинации определяется первой частотой: чип второй — 29 м. У G1 + G2
чип 587 м на обеих частотах, и комбинация по СКО в 2,5–8 раз шумнее остальных пар.
При равных весах она ухудшала бы решение по всем системам.

Учитываются:

- поправки часов КА (с релятивистской);
- вращение Земли за время распространения;
- тропосфера (Саастамойнен);
- ионосфера (Клобучар) — для одночастотных измерений;
- групповая задержка TGD КА GPS — для одночастотных измерений: часы КА в эфемеридах
  отнесены к ионосферно-свободной комбинации, на частоте f поправка −TGD·(f1/f)²;
  Galileo E1 (часы I/NAV — по паре E1, E5b) — −BGD(E1, E5b); BeiDou B1I (часы — по B3I) —
  −TGD1.

Скорость и дрейф часов определяются по доплеровским измерениям.

3.4.5 **Двухчастотный режим.** Включается полем `dual` структуры приёмника. Сигнал второй
частоты задаётся по системе (`sig2`):

| Система | Первая частота | Вторая частота (по умолчанию) | ВЧ-канал второй частоты | γ = (f1/f2)² |
|---|---|---|---|---|
| GPS | L1 C/A | L2CM или L5Q | 2 / 4 | 1,647 / 1,793 |
| ГЛОНАСС | G1 | G2 | 3 | (9/7)² = 1,653 |
| Galileo | E1-B | E5a-Q | 4 | 1,793 |
| BeiDou | B1I | B3I | 6 | 1,514 |

Канал второй частоты пускается по каналу первой того же КА после привязки времени излучения:

- фаза кода — по времени излучения на первой частоте: (t_tx mod период кода)·частота
  чипов. Из времени излучения вычитается разность ионосферных задержек
  (γ − 1)·I1/c по модели Клобучара, если решение уже есть. Вторичный код (NH20 у L5Q,
  CS100 у E5a-Q, NH20 у B3I) синхронизируется при слежении;
- доплер — пересчётом сглаженного доплера первой частоты (τ = 1 с, без шума ФАП)
  по отношению несущих f2/f1. У ГЛОНАСС литера общая для G1 и G2.

Поиск не нужен: начальная ошибка по задержке определяется ошибкой модели ионосферы.
Это единицы метров — меньше 0,1 чипа L5 и E5a (29 м). Особенности сигналов второй частоты:

- L2CM — половины чипов CL в копии обнуляются (режим TDM коррелятора), период кода
  и символа — 20 мс;
- E5a-Q, L5Q — пилотные сигналы, когерентное накопление 20 мс со снятием вторичного кода.

Псевдодальность второй частоты строится так. Время излучения внутри периода кода
берётся по фазе её кода, целое число периодов — по первой частоте: разность времён
излучения приводится к интервалу ± половина периода. Ионосферно-свободная комбинация:

P_IF = (γ·P1 − P2)/(γ − 1).

Модель ионосферы для неё не применяется. Часы КА исправляются на групповую задержку
комбинации:

gd_IF = (γ·gd1 − gd2)/(γ − 1),

где gd — задержка сигнала относительно опорной для часов КА в эфемеридах (`sig_gd`):

| Сигнал | gd |
|---|---|
| GPS L1 C/A, L5 | TGD (часы LNAV — по L1/L2; ISC L5 из CNAV не принимается) |
| GPS L2C | γ12·TGD |
| Galileo E1 | BGD(E1, E5b) (часы I/NAV — по E1/E5b) |
| Galileo E5a | BGD(E1, E5b) + (γ − 1)·BGD(E1, E5a) |
| BeiDou B1I | TGD1 (часы D1 — по B3I) |
| BeiDou B3I | 0 |
| ГЛОНАСС G1 | 0 (часы — по L1) |
| ГЛОНАСС G2 | Δτn (строка 4) |

Пара BeiDou выбрана B1I + B3I, а не B1I + B2a. Причина: часы D1 отнесены к B3I, поэтому
для пары B1I + B3I достаточно TGD1. Для B2a нужна задержка TGD_B2ap из сообщения B-CNAV.

3.4.6 **Сглаживание кода по фазе несущей.** Псевдодальность каждого канала сглаживается
фильтром Хэтча:

Ps(k) = P(k)/m + (Ps(k−1) + Φ(k) − Φ(k−1))·(m − 1)/m,

где Φ — фаза несущей из «зеркала» NCO в метрах, m — число измерений, не более окна
(100 с). Фильтр сбрасывается в трёх случаях:

- срыв слежения;
- перерыв в измерениях более 5 с;
- расхождение кода и фазы более 30 м (проскок фазы).

Сглаживание идёт с момента привязки времени излучения, в том числе до приёма эфемерид.
Ионосферно-свободная комбинация сглаженных P1 и P2 не имеет расхождения кода и фазы
из-за ионосферы: составляющие L1 и L2 взаимно уничтожаются.

Для веса в решении (подраздел 3.4.4) фильтр ведёт эффективное число независимых
измерений кода в сглаженной ПД (`hs_m`):

- до заполнения окна — m (простое среднее);
- после — 2m − 1 (экспоненциальное среднее).

Шум ССЗ коррелирован на интервале около 1/(2Bn). Поэтому при интервале измерений dt
короче этого значения число умножается на 2Bn·dt.

3.4.7 **1PPS.** Момент следующей секунды GPST вычисляется по последнему решению
с учётом дрейфа и пересчитывается в такт 96 МГц. Остаток квантования выдаётся как qErr.

3.4.8 **Помехи.** Используются спектр Уэлча (1024 точки, окно Ханна) и пики выше 6 дБ
над медианой. Частота уточняется максимумом ДПФ по снимку. Фильтр включается при
J/N ≥ −20 дБ, дизеринг — при J/N < −5 дБ.

# 4 Используемые технические средства

4.1 Микроконтроллер STM32H743 (1 МБ ОЗУ, 2 МБ флеш-памяти). ПЛИС модуля
с конфигурацией из `fpga/rtl` подключена к шине FMC (банк 1, 16 бит, мультиплексированный
режим, сигнал NWAIT).

4.2 Для проверок на ПК: Linux, gcc (C99), Python 3 с пакетами numpy, pynmeagps, pyrtcm.

4.3 Объём (вычислительное ядро, `make -C sw/fw mcu`, arm-none-eabi-gcc -O2, Cortex-M7):

- код и константы — 427 КБ, из них таблицы дальномерных кодов 357 КБ;
- статические данные — 452 КБ, из них буферы захвата 395 КБ;
- буферы режима длительного накопления — 384 КБ на группу из 8 PRN, выделяются
  в SRAM1–3 и DTCM.

Всего ОЗУ около 836 КБ из 1 МБ, флеш-памяти — около 0,43 МБ из 2 МБ.

# 5 Вызов и загрузка

5.1 ПО МК загружается во флеш-память МК через SWD или через загрузчик по USB/UART.
Конфигурация ПЛИС хранится во флеш-памяти W25Q128 и загружается ПЛИС при включении.

5.2 На ПК: `make -C sw/fw test` — модульные и сквозные тесты; `make -C sw/fw test-long` —
сквозные тесты «ПЧ → координаты, 1PPS» (GPS; GPS + ГЛОНАСС; GPS L1 + L2C;
GPS + Galileo + BeiDou; двухчастотные пары L1 + L5, G1 + G2, E1 + E5a, B1I + B3I по четырём
системам), слежение при динамике и слабых сигналах (около 70 мин).

# 6 Входные данные

6.1 Входные данные ПО МК:

- результаты корреляторов: I/Q трёх отводов, номер отсчёта сброса;
- снимки отсчётов каналов;
- метки времени событий ПЛИС (EXTINT, опора);
- состояние MAX2771 и питания антенны;
- команды по UART, USB и CAN.

6.2 Для проверок на ПК — отсчёты ПЧ от имитаторов в тестах и навигационные файлы
RINEX (IGS).

# 7 Выходные данные

7.1 Выходные данные ПО МК:

- сообщения NMEA-0183 4.11 (GGA, RMC, GSA, GSV, GST, ZDA);
- RTCM 3.3 (MSM7 для GPS, ГЛОНАСС, Galileo, BeiDou; 1005);
- собственный двоичный протокол: кадр 0x4D 0x38, класс, идентификатор, длина, данные,
  CRC-16/CCITT. Сообщения: решение (01/01), сырые измерения (02/01), эфемериды (02/02),
  состояние каналов (03/01), ИТМ (04/01);
- уставки 1PPS (регистр PPS_T) и поправка qErr;
- настройки режекторного фильтра ПЛИС.
